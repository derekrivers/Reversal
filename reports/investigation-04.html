3. Golden-goal and abandonment paths

006d4250 is a small post-goal rule check. Its literal behavior is:

stop_after_goal = (uint16(period_target) != 495)
               && (uint16(period_target) != 990)
               && ((fixture_flags & 0x80) != 0)

Inspected goal callers set match+0x1a8 when this check returns true. A later branch on that latch emits 0x1fd2, which maps to config 146, EVENT_GOLDEN_GOAL. The period helper then terminates extra time when the latch is set. The compact predicate itself does not validate that the target is a supported extra-time period, test that a goal occurred or check a tied score; its callers supply that context. Sentinel and unsupported targets are included in the instruction comparison.

The exceptional dispatcher path emits 0x217b, config 571, EVENT_MATCH_ABANDONED_PITCH_CONDITION. Its signed-byte minute threshold is at match+0xf638; -1 disables the inspected check. The path sets score sentinels to 0xfd and returns status 8. The weather/condition logic that selects the threshold remains to be traced.

At end of config parsing, the loader converts each positive divisor to trunc(maxDivisor * 10 / divisor) and sums the resulting weights. The enqueue path draws a bounded random value from that total and finds the first cumulative weight exceeding the draw. Treating the raw config number as a direct proportional weight would reverse its effect. This normalization was statically traced; full-loader equivalence is not claimed.

The 14-byte occurrence record's byte +0xd is now identified as a signed text-segment cursor, initially -1. 006d78b0 advances through pipe-separated game text and uses event-code bit 0x8000 to mark continuation. Companion +0xc is the display-ring index; +0xe is used by the history-copy cursor. Formatters at 006d7b00 and 006d8d10 read the game and report text pointers respectively. Their raw decompiler prototypes are damaged by stack-probe handling and have not been imposed as recovered signatures.

4. Random-choice path

The helper at 0090cfc0 has 3,772 observed exact-entry call references from 359 containing functions. Its state is shared globally. Capturing a seed alone at an arbitrary point is insufficient to recreate the current cursor, offset and generator state without the intervening call history.

state = (state * 214013 + 2531011) mod 2^32
crt_output = (state >>> 16) & 32767

For a nonzero small bound:
  advance table cursor
  on wrap: reset cursor and refresh offset with crt_output
  dividend = signed32(offset + table[cursor])
  result = signed_remainder(dividend, bound)
  if bound is negative: negate result

The initialization routine 0090d0a0 sets a supplied CRT seed, derives the cursor from one CRT draw modulo 51,000 and the offset from a second draw modulo 65,535. A zero seed invokes a time-related helper; that path and save/load restoration remain untested.

The emulator admitted only the selected RNG instruction ranges, mapped synthetic memory and enforced return/time/instruction budgets. No Windows services or full game process were started.

  • Zero and negative bounds, table endpoints, several offsets and synthetic CRT states.

This is an instruction-level equivalence check for sampled inputs on the supported branch. It does not establish probability quality, exhaustive input coverage, full-game determinism or match-result equivalence.
