# Investigation 28-B: merge collection dependencies

This unit maps the complete local bodies at virtual addresses `0068d020` and `0068d0d0` in the pinned 7,192,576-byte CM01/02 3.9.68 PE32, SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. Their PE **file offsets** are `0x28d020` and `0x28d0d0`; body lengths are 17 and 221 bytes. The read-only native exports came from restored checkpoint 27, private archive SHA-256 `d2836fd1b28d194dbfda32454106f9af23495809f09a408ed1ee072e6c4b7de1`. The [site map](../evidence/merge-dependencies-28-sites.json) pins export/preflight hashes, exact-old names, original body hashes, 7 and 71 instruction starts, all 6 and 73 local CFG edges, memory operands, four call instructions and return sites. The [extractor](../scripts/extract_merge_dependencies_28.py) verifies every original byte decodes into a complete contiguous body, and compares each original instruction address, mnemonic and operand with the independent native export. All local targets are instruction starts and all starts are reachable assuming returning callees. The call graph stops at direct callee entry.

## `0068d020`: fourteen-byte initializer

ECX supplies the receiver pointer. The routine copies it to EAX, sets ECX to zero, then writes zero in this **order**: DWORD at receiver `+2`, DWORD at `+6`, DWORD at `+0xa`, WORD at `+0`. The unaligned stores cover exactly `[receiver,receiver+14)` with no holes. It uses no stack arguments or callees, preserves EDX/EBX/ESI/EDI/EBP, and returns EAX=receiver, ECX=0 with ordinary `RET` (ESP advances four bytes). `XOR ECX,ECX` changes EFLAGS; this reconstruction does not compare flags. It checks neither null nor mapped memory. The 14-byte layout is consistent with a 16-bit count at `+0` and three 32-bit pointers at `+2/+6/+a` in the callers, but field ownership and collection invariants come from surrounding uses, not this initializer alone.

The [original-entry oracle](../evidence/merge-initializer-28-oracle.json.gz) executes all seven original instructions and six edges over 256 synthetic cases: 16 deterministic byte patterns at each of 16 mapped receiver offsets, including unaligned positions. It records 1,792 steps, entry-to-`RET` registers, ordered data writes and stack return read, plus SHA-256 of the **entire** 4 KiB receiver page and 4 KiB stack page after execution. The [TypeScript reconstruction](../reconstruction/merge-initializer-28.ts) and [checker](../reconstruction/check-merge-initializer-28.ts) recreate all synthetic inputs and compare those observations, including preserved registers and the exact return EIP/ESP. They reject invalid receiver ranges. This is a bounded behavior claim for stable mapped memory and normal returns, not a connected merge execution.

## `0068d0d0`: append a copied record

ECX is a receiver with an unaligned WORD count at `+0`, a DWORD first-node pointer at `+2`, and a DWORD tail pointer at `+6`. The routine reads two **callee-cleaned** arguments at entry stack `+4` (source pointer) and `+8` (copy size, with low 16 bits used by the constructor). All three normal returns use `RET 8`, so ESP rises 12 bytes from entry: four for the return address and eight for those arguments. It preserves ESI through a push/pop. It installs a thread-local SEH frame at `FS:[0]`, with handler address `0095cb56`, saves the prior frame and restores `FS:[0]` on every normal return. Local unwind state is set to zero on the empty route or one on the nonempty route; exception behavior through that handler is not mapped here. EAX returns the new node's DWORD at `+0` on success, which the constructor stores as its allocated payload pointer. On an observed local null-node route, EAX returns zero. ECX at normal return contains the prior SEH frame pointer because the epilogue loads it before restoring `FS:[0]`; it is not preserved as the receiver. EDX is used as a scratch register on the nonempty success route. EFLAGS and transitive callee register/exception effects are not certified.

| Local route | Ordered direct effects and return |
| --- | --- |
| Count zero | Request 14 bytes from `00944cf1`. If allocation is nonnull, call `0068cfc0(new_node, source_pointer, copy_size)`; store resulting EAX at receiver `+2`. If it is null, return zero with count and tail unchanged. If nonnull, increment count as a WORD, store new node at receiver `+6`, read its DWORD `+0` as return value. |
| Count nonzero | Request 14 bytes. If allocation is nonnull, call the same constructor. Store resulting EAX at `[old_tail+6]`; reread this link. If null, return zero without count/tail update. If nonnull, write old tail to `[new_node+0xa]`, reread `[old_tail+6]`, increment receiver count as a WORD, set receiver `+6` to that new node, read its DWORD `+0` and return it. |

Both routes pass `14` to the allocator wrapper and push the two caller arguments for the constructor. The allocator wrapper's return and constructor behavior are unresolved transitive effects for this unit. The native export of `0068cfc0` shows that it allocates/copies a size derived from signed low 16 bits and sets node links, but its own proof belongs to R28-C. Consequently, negative/large sizes, allocation failure/exception policy, payload ownership, invalid pointers, stale tail links, races and aliasing are outside any execution claim here. The nonempty null route writes zero to old tail `+6`; it is not a pure no-op failure path. The WORD count wraps modulo 65,536 if a caller reaches that state. The body does not validate that the count, head and tail are mutually consistent.

R26-A's `0062be00` constructs a 6-byte key/kind/severity record and calls this routine on its no-candidate route; its connected merge loop still depends on allocator, constructor and list invariants. `0068d020` is also called separately from other object constructors. The [exact-old name proposals](../evidence/merge-dependencies-28-annotations-proposal.json) are name-only and require the coordinator to recheck the canonical project. These two functions add local contracts; only the initializer has a validated TypeScript domain.

## Integrity and limits

The [Python negative receipt](../evidence/merge-dependencies-28-negative.json) records byte-identical normal/`python -O` regeneration of site evidence and oracle, pinned-PE rejection, independently resealed wrong native operand rejection, and independently resealed wrong old-name rejection. The [TypeScript negative receipt](../evidence/merge-initializer-28-negative.json) records rejection of changed return register, reordered effects, changed full memory, changed preserved-register expectation and corrupted oracle. Node 24 runs the task checker. The [privacy receipt](../evidence/merge-dependencies-28-privacy.json) checks the retained schema and synthetic schedule. Synthetic page and stack bytes use published arithmetic patterns only; the evidence contains hashes, addresses, observations and those input parameters, not game memory or executable bytes.
