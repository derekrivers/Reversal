# R23-A: indexed status-band helper

The complete local body at virtual address `0062c400` is 271 bytes and 88 x86 instructions. Its original file offset is `0x22c400` in the pinned 7,192,576-byte PE32 executable, SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. The read-only Ghidra 12.1.4/JDK21 export came from an independently reopened checkpoint-22 archive (SHA-256 `ea4c9888f34fe4282434e41a38e842cabec61ded30d064d0417a166e18f7fcc2`). The export manifest and exact-old preflight have SHA-256 `b8d302c629ba6fbb98cb45315ee5df6f238b5b9a8e02a1c8220db3e2f384844d` and `c7128da6c29d92931c1e096fc17112f28b73a4cd0276f7869e80a6800aee9e3a`.

`scripts/extract_match_status_23.py` checks the PE, metadata, native export and every decoded instruction address, mnemonic and operand. All 88 instructions are structurally reachable from entry. The [site evidence](../evidence/match-status-23-sites.json) records four local branches, six direct calls, one direct nonframe write and three `RET 4` exits. The decompiler output was a clue; widths and signed tests here follow original instructions.

## Local contract

Entry `ECX` is the receiver. Entry `ESP+4` is a pointer to a 32-bit index, rather than the index itself. ESI and EDI are saved, and every local exit uses `RET 4`. The immediate caller `0062c590` is context only.

- A null pointer enters a diagnostic chain: calls `00944cff`, `0090d130`, `00944c9f` and `005e8290` in that order, writes a zero DWORD to `00b67a34`, then clears **AL**. The calls' side effects and failure/termination behavior are unresolved. The return's upper EAX bits are not guaranteed zero.
- For a nonnull pointer, `MOV ECX,[ESI]` precedes reading the runtime DWORD count at `00ae2364`. Signed `CMP/JGE` returns when `*pointer >= count`, clearing AL while keeping the upper 24 bits of the count in EAX. This path calls no helper and directly writes no nonframe memory.
- For `signed *pointer < signed count`, it calls `0062c680` with receiver and pointer. It then **reloads** `*pointer`, computes `index*31` modulo 2³², freshly reads the receiver's first DWORD, and loads the DWORD at `table+index*31+14`. The local body has no lower-bound check for a negative index. A record ID of `-1` returns with AL zero.
- Otherwise, it computes `record = receiver[1] + ID*48`, reads two DWORDs at `record+32/+36`, and calls `0054cc30` with a local output pointer. The local output is read as a **signed WORD** at `local+8` and an **unsigned WORD** at `local+10`. The arithmetic computes `unsignedWord*365 + signedWord` in wrapping 32-bit EAX. A signed comparison with the record's signed WORD at `+42` returns AL=2 if the value is below it. Otherwise a signed comparison with the record's signed WORD at `+40` sets AL to one if below, zero if not. Only the low byte is a classification; high EAX bits retain intermediate arithmetic.

The status refresher `0062c680` and converter `0054cc30` are explicit transitive boundaries. In particular, the first can mutate state before the post-call pointer and receiver loads, and the second produces the stack WORDs consumed by the formula. The six direct calls include no direct RNG target, but transitive RNG and other writes have not been ruled out. Invalid pointers, aliasing, call failures and live index validity are unproven.

## Original-instruction guard validation

The headless [TypeScript guard](../reconstruction/match-status.ts) covers only the nonnull, mapped, stable, disjoint pointer path where `signed *pointer >= signed count`. Unicorn 2.1.4 executes the **original entry through `RET 4`** for 43 synthetic cases, totaling 688 executed instruction steps and 16 distinct instruction starts. Counts include both signed extremes and values around zero; indices include equal and greater boundary cases. The [oracle](../evidence/match-status-23-guard-oracle.json) retains registers, trace, pointer/count read order and absence of external writes. The [checker](../reconstruction/check-match-status.ts) verifies the schedule, trace, RET4 stack effect, EAX/ECX result, EDX/ESI/EDI preservation and the original oracle SHA-256 `55a960c68ff9d7d01ceba32b49da7cd1e902a2c6291a36e706ccf33cb846a36c`. EFLAGS and the other body paths are outside this comparison. This is path validation, not a claim of whole-body equivalence.

Normal and `python -O` runs generated byte-identical site and oracle JSON. A changed specimen byte and changed native operand were rejected before output in both modes. A local diagnostic resealed the mutated export and temporarily supplied its new manifest hash, confirming the independent original/native operand comparator also rejected it. The public extractor remains pinned to the original manifest. The checker rejected a changed TypeScript result and tampered oracle; see [negative receipt](../evidence/match-status-23-negative.json). The original PE, native exports and project remain private; public evidence contains synthetic numbers and site metadata, not executable bytes, bulk decompilation or game records. The native name in the [proposal](../evidence/match-status-23-annotations-proposal.json) has not been applied.
