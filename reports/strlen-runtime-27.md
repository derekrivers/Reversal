# Investigation 27-B: runtime `_strlen`

The pinned SI 3.9.68 PE32 x86 executable (SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`) contains the 123-byte `_strlen` body at virtual address `009488e0` (raw file offset `005488e0`). Its existing Ghidra library name and comment are preserved. This is the R24 path formatter's callee; the formatter and locale-copy caller paths are context, not validated by this unit.

The [complete local instruction evidence](../evidence/strlen-runtime-27-sites.json) compares all 44 Capstone instruction addresses, mnemonics and operands with the read-only native export. Every branch target stays in the local body, and it contains no calls or explicit memory writes. The first argument is read from `[ESP+4]`. On a misaligned pointer, the body scans one byte at a time until it sees NUL or reaches four-byte alignment. It then loads an aligned four-byte word, applies `((~word ^ (word + 0x7efefeff)) & 0x81010100)`, and rereads candidate words for bytewise NUL checks. The four return sites calculate the byte distance to NUL; `RET` leaves the caller's argument on the stack. `ECX` is restored to the argument pointer. `EDX` is preserved on an early leading-byte exit and clobbered by the detector on word-scan exits.

The [original-entry oracle](../evidence/strlen-runtime-27-oracle.json.gz) executes the unpatched PE body in Unicorn 2.1.4 over 576 explicitly mapped synthetic strings: all four alignments, selected first-NUL offsets from 0 through 95, and four nonzero fill patterns. The [TypeScript reconstruction](../reconstruction/strlen-runtime-27.ts) agrees on length, all eight compared registers, stack, return PC, and the ordered width/value of every source and stack read. Coverage is all 44 instruction starts and all 48 local CFG edges across 58,526 original x86 steps. No write occurred. The captured trace has 848 one-byte source reads, 6,027 four-byte source reads and 1,728 four-byte stack reads. Candidate words were reread in 552 cases; 420 cases read beyond the first NUL as part of a four-byte word, by at most three bytes. Each of those bytes was mapped in the admitted source region.

The [negative-check receipt](../evidence/strlen-runtime-27-negative.json) records five specimen/native/oracle integrity rejections, six model-comparison mutations, nine unsupported-input checks, and a repeat under optimized Python. The native export manifest SHA-256 is `bbd00280029a738f4f4dfa6462c7d34a4379887626749d9f20eef20873655f14`; exact-old preflight SHA-256 is `fb1be5075c72e92045f4d802f649665801d8ebc85b049a25e0f652e282f6015d`; preserved checkpoint-26 archive SHA-256 is `4acf11ca1ab79b275436c6365813904d87634436de1723ce24a2274f83a087c4`. The private PE/native inputs and full exports are not included here.

This validates a bounded local runtime function. It does not establish behavior for unmapped or faulting pointers, concurrent source changes, caller formatting, locale decisions, or game output. EFLAGS and timing were not compared. The observed four-byte read past NUL makes a mapped-word precondition material; a NUL byte alone does not guarantee the original body can read safely at a page boundary.
