# Investigation 26-A: status invalidation and keyed kind/severity merge

This unit maps the complete local bodies at virtual addresses `0062e700` and `0062be00` in the pinned 7,192,576-byte PE32, SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. Their file offsets are `0x22e700` and `0x22be00`; body lengths are 284 and 342 bytes. The read-only native exports are from independently restored checkpoint 25, archive SHA-256 `670587a05d1f75ae729c32a93e3ba5739f3d513a3c27126ddd4d9185b8620b6a`. The [site map](../evidence/match-dependencies-26-sites.json) pins its private manifest/preflight, body hashes and 97/117 original instructions. Capstone 5.0.7 matches every instruction address, mnemonic and operand with the native assembly; every local branch target is an original instruction start and all starts are reachable in the local CFG assuming returning callees. The map enumerates branches, calls, explicit memory operands/widths and returns. Implicit stack writes/reads from PUSH, POP, CALL and RET are additional ABI effects; exceptions and callee CFGs are outside that graph.

## `0062e700`: invalidate a linked status record

ECX supplies a receiver; stack DWORDs supply a player-like pointer `P` and notification flag `F`; both exits use `RET 8`. EBX and EDI are saved on every route, ESI only after finding a non-sentinel link, and EBP is untouched. A 512-byte stack frame holds two diagnostic buffers. This body installs no local SEH frame. EAX/ECX/EDX and arithmetic flags are volatile; its apparent void interface does not force a fixed EAX return.

| Sites | Ordered local behavior |
| --- | --- |
| `0062e711..0062e779` | Null `P` enters diagnostics. Calls are `00944cff(009e7f28,0,0,bufferB,bufferA)`, then `0090d130(bufferB,bufferA,0xc87)`, then `00944c9f(00ae24d0,009870e8,previousEax)`, then `005e8290(009870e0,00ae24d0,0)`. Caller stack adjustments are 20 then 36 bytes for these groups. The final direct external write is DWORD `00b67a34=0` at `0062e76b`. EAX is the last callee's result. Diagnostic formatting, UI/error handling and all transitive writes remain external. |
| `0062e77c..0062e786` | Read signed32 `I=*P`, then signed32 global count at `00ae2364`. `I>=count` exits with EAX=I, ECX=count and original EDX. There is no separate nonnegative-index check. |
| `0062e78c..0062e79e` | Read table base `T=*(DWORD*)receiver`; calculate `R=T+31*I` with 32-bit wrap; read link `L=*(DWORD*)(R+0xe)`. `L==-1` exits with EAX=`ffffffff`, ECX=R, EDX=T. Other negative links are accepted by this local guard. |
| `0062e7a0..0062e7c2` | Read record base `B=*(DWORD*)(receiver+4)`; calculate `S=B+48*L` with wrap; read status BYTE `*S`. Status `0x51` bypasses `0058e340`; otherwise invoke that callee with ECX=`*(DWORD*)(receiver+0xc)` and stack args `(R+0x14,R+0x18,S)`. The call site expects 12 bytes of callee stack cleanup. It can mutate state before subsequent guards. |
| `0062e7c2..0062e7f5` | Read stack flag F. Zero bypasses notification. Otherwise read unaligned DWORD `*(P+0x39)`; zero also bypasses. Nonzero calls `00600a50(value,0,1,0,0)` with caller cleanup of 20 bytes. A zero EAX result bypasses the final call; nonzero reads current BYTE `*S`, replaces only CL, then invokes `00630ee0` with ECX=receiver and args `(P,1,ECX-with-low-byte-replaced,0,0)`. The final clear can therefore target a different row than the original read if earlier callees changed index/table. EAX=T and EDX=`31*I`; ECX is whatever preceding local/callee operations left. |

No direct RNG helper or floating instruction appears. Transitive calls can still consume RNG, fault, throw or change other state. The local order and width of invalidation writes are established; the meaning of status `0x51`, valid record lifetime, callback side effects and reachable live-game pointer ranges remain open.

## `0062be00`: keyed kind/severity merge

ECX supplies a receiver, with three stack pointers `(keyPtr,kindPtr,severityPtr)`; four normal return sites all use `RET 0xc`. Key is a DWORD; kind and severity are BYTEs. This body saves ESI/EDI, and temporarily EBX/EBP on one branch. Its prologue reads `FS:[0]`, pushes state `-1`, handler `0095b0db` and the old head, then installs a stack registration at entry ESP minus 12. The body allocates another 12 bytes plus saved registers. Every normal return restores the old head to `FS:[0]`; ECX then equals that old head. The handler's exception/unwind actions have not been mapped or executed.

| Sites | Ordered local behavior |
| --- | --- |
| `0062be1c..0062be50` | Read receiver `+0x28`. If null, call `00944cf1(14)` with caller cleanup of 4, save allocation pointer on stack and set unwind state to 0. Nonnull allocation calls `0068d020` with ECX=allocation; null allocation uses EAX=0. Set unwind state back to -1 and write returned pointer to receiver `+0x28`. There is **no** null-result guard before the next dereference; a null result reaches a read at address 2 and then a write at address 10 rather than a graceful normal failure. Allocation, construction and exception behavior remain external. |
| `0062be53..0062be5f` | Reload collection-like pointer `C=*(receiver+0x28)`, read unaligned DWORD `*(C+2)`, write it to unaligned DWORD `*(C+0xa)`, reload C into ECX and unconditionally call `0068d1b0`. **Every normal path executes this callee at least once.** The field reset suggests a cursor, but the callee's enumeration and mutation behavior is unresolved. |
| `0062be64..0062be7e` | EAX is treated as a candidate row pointer. Null goes to insertion. Otherwise read candidate DWORD `*EAX`, then key DWORD `*keyPtr`. Equal goes to merge; unequal reloads `receiver+0x28` into ECX and calls `0068d1b0` again. First equal candidate returned by that callee is selected. The local loop has no iteration bound. |
| `0062be80..0062beb9` | No candidate: reread key DWORD, put it in the stack temporary; read incoming severity BYTE **before** incoming kind BYTE, form six bytes `[keyDWORD,kindBYTE,severityBYTE]`, and call `0068d0d0(temp,6)` with ECX reloaded from receiver `+0x28`. The call site expects 8 bytes of callee cleanup. No local output-pointer write occurs on this route; the callee may write indirectly. EAX is its returned value, uninterpreted by this body. Restore SEH and return. |
| `0062bebc..0062bec5` | Found candidate: read row kind BYTE `+4`, compare bitwise equality with incoming kind BYTE. The branch does not require a nonnegative kind. |
| `0062bec7..0062bf21` | Same kind: read row severity BYTE `+5`, then incoming severity BYTE; sign-extend each to signed32 and add. Signed sum **greater than 100** takes the capped arm: read row kind at `0062bee1`, write row severity 100 at `0062bee4`, then write the previously read kind to incoming kind at `0062bee8`. Otherwise compute the low byte with `ADD CL,DL` and write row severity at `0062bf04`, including wrap below -128; this uncapped arm then reads row kind at `0062bf07` and writes incoming kind at `0062bf0a`. There is no lower clamp. Both arms then read updated row severity and write incoming severity before restoring SEH. EAX remains the selected row pointer. |
| `0062bf24..0062bf53` | Different kind: read row severity BYTE, then incoming severity BYTE, compare as **signed8**. Incoming greater writes row severity first, then reads incoming kind and writes row kind. Equal or lower retains both row fields. Finally read row kind, write incoming kind, read row severity, read saved old SEH head, write incoming severity, restore nonvolatiles/SEH and return. EAX remains the row pointer. |

For example, same-kind severities 100 and 1 cap to 100, but bytes `80h+80h` are signed -128 plus -128 and store `00h`. In a different-kind comparison, incoming `80h` loses to stored `7fh`; ties retain the prior kind. These are static consequences of `MOVSX`, `JLE` and byte writes, not executed merge fixtures. Aliased pointers can alter later reloads; the exact write/read order above is part of the local contract. Collection layout beyond these accessed offsets, element ownership, insertion success, allocation failure recovery, callback reentrancy and termination remain unresolved. There is no no-callee whole-function execution claim for this body.

## Original-entry TypeScript validation

The [oracle](../evidence/match-dependencies-26-oracle.json) runs actual `0062e700` instructions from entry through `RET 8` with Unicorn 2.1.4. Its 77 cases comprise 36 signed count-guard pairs, five sentinel-link cases and 36 status-`0x51` invalidations with notification bypassed by zero flag or null `P+0x39`. This totals 2,185 executed steps and 44 of 97 instruction starts. The count pairs include signed32 extrema. Mapped negative indices (-2/-1) and negative link -2 deliberately verify the absence of additional local lower-bound guards; their validity in game state is not established.

The [TypeScript implementation](../reconstruction/match-dependencies-26.ts) and [checker](../reconstruction/check-match-dependencies-26.ts) compare EAX/ECX/EDX, ordered interleaved external reads/writes, complete SHA-256 digests of five external synthetic regions, RET8 stack movement and EBX/ESI/EDI/EBP preservation. All memory is synthetic and disjoint: stable player/receiver/table/record/global regions filled with an authored pattern. Stack contents and EFLAGS are outside the TypeScript comparison; stack cleanup and preserved registers are checked. No original game data, external callee, diagnostic route, non-`0x51` update or live notification is executed. Unsupported routes throw before a local invalidation write. The implementation retains the final player/table reloads.

The [negative receipt](../evidence/match-dependencies-26-negative.json) reproduces sites and oracle byte-for-byte in normal and optimized Python, rejects changed specimens in extractor/emulator, rejects changed native exports, and reaches the operand comparator with independently resealed immediate and width mutations. It also rejects mutated TypeScript registers, missing memory effects and tampered oracle bytes. All integrity gates use explicit exceptions and remain active under `python -O`. Node 24.19.0 runs the new checker and the repository `npm run check`. The coordinator can add this owned checker to the shared check runner during integration.

[Name proposals](../evidence/match-dependencies-26-annotations-proposal.json) retain exact-old preflight evidence. Both are research names for local behavior. R21 `007160e0` is existing context only; no new entry or duplicate validation is claimed. These contracts do not establish a connected shot, penalty, match or complete status lifecycle.
