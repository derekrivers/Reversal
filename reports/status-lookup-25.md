# Investigation 25-A: refreshed status lookup and byte helpers

This bounded investigation maps the complete local bodies at virtual addresses `0062ed70`, `0062ec00`, and `0062ece0` in the 7,192,576-byte PE32 executable with SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. Their file offsets are `0x22ed70`, `0x22ec00`, and `0x22ece0` respectively. The read-only Ghidra exports come from checkpoint 24, archive SHA-256 `77fb2072a25ff030ab3c0e58c5cd289730a9a8c5345ceaaf56e948e727c1dd0b`; the private export manifest and exact-old annotation preflight are pinned in [findings](../evidence/status-lookup-25-findings.json).

Capstone 5.0.7 decoded every original PE instruction and compared each address and operand with the native assembly. The [site map](../evidence/status-lookup-25-sites.json) retains body hashes, 4/28/60 instruction counts, all branches, calls, memory operands, and returns. All starts are reachable in each local CFG. The original-byte ranges and bulk native exports remain private.

## Local contracts

| Entry | ABI, ordered effects, limits |
| --- | --- |
| `0062ec00` | One stack DWORD, `RET 4`. `MOVSX` interprets its low byte as signed8, multiplies it by 13, and reads one byte at `009e7ad9 + 13*signed8`. `MOV AL` replaces only EAX's low byte, leaving upper bits from sign extension. ECX ends at three times that signed8 value modulo 2³². No call, write or table bounds check. Table contents and caller range are separate questions. |
| `0062ece0` | ECX is the lookup object and the stack argument is a player pointer; `RET 4`. Null pointer, signed32 `*player >= *00ae2364`, null DWORD at `player+61h`, or negative signed8 row byte at `+12h` take AL-zero paths. The row address is `*(DWORD*)object + 31*(*player)`; the active-pointer check precedes its calculation. On the successful path the signed8 row byte `+13h` is returned if it exceeds 1, otherwise EAX is 1. The failure paths execute `XOR AL,AL`, so EAX's upper bits can come from the incoming EAX, the index, or the row address. EDX is the pointer until row calculation, then `31*index`; ESI is preserved. No direct call or write, and no negative-index or row bounds guard. |
| `0062ed70` | ECX is the lookup object, one player pointer argument, `RET 4`. Null player enters diagnostic calls `00944cff`, `0090d130`, `00944c9f`, `005e8290`, then writes global DWORD `00b67a34=0` and returns 0. Nonnull signed32 index `>= *00ae2364` returns 0 without a call. Passing index invokes `0062c680` **before** reading signed32 mapping at `*(DWORD*)object + 31*index + 0eh`; mapping `-1` returns 0, otherwise return `*(DWORD*)(object+4) + 48*mapping` modulo 2³². There is no explicit negative-index or post-refresh mapping bound check. The refresh can write state and consume RNG, so this is not a pure accessor. |

`0062ece0`'s `CMP byte ptr [...],0xff; JLE` is a **signed** byte comparison. It rejects every `80h..ffh` value at row `+12h`, not only `ffh`. Its `CMP AL,1; MOVSX EAX,AL; JG` compares the signed byte, then either returns that signed value for 2..127 or forces 1. These widths and branch orders come from original instructions, rather than the decompiler's inferred types.

## Executed TypeScript scope

The [oracle](../evidence/status-lookup-25-oracle.json) executed original entries to `RET 4` in Unicorn 2.1.4 against synthetic mapped memory. [TypeScript helpers](../reconstruction/status-lookup-helpers.ts) and [checker](../reconstruction/check-status-lookup-helpers.ts) compare return registers, ordered external memory reads, no external writes and stack/nonvolatile preservation. The cases are 256 signed-byte table inputs (all four instruction starts), 32 byte-condition cases (all 28 starts, including sentinel, signed-return and early exits), and 43 signed count-guard cases at `0062ed70` (16 starts). This totals 331 cases and 2,425 executed instruction steps. The table uses synthetic bytes; it is not a recovered copy of the game table.

`0062ed70`'s execution claim covers only nonnull mapped pointer cases with signed index at least the global count. Its diagnostic route and `0062c680` refresh route remain static, as do all transitive helper effects. The row helper cases use disjoint stable mapped object, player and global storage. They do not establish real-game pointer validity or caller reachability. No connected penalty or shot behavior is claimed.

[Negative checks](../evidence/status-lookup-25-negative.json) reproduce static and oracle evidence byte-for-byte in normal and `python -O` modes, reject a changed specimen and changed native operand (including a resealed export reaching the operand comparator), and reject changed TypeScript output and oracle bytes. Node 24 checker and `npm run check` pass. The existing `0062ed70` Ghidra name/comment should remain exact; [name-only proposals](../evidence/status-lookup-25-annotations-proposal.json) cover the two previously unnamed byte helpers. They are research labels, not original symbols.
