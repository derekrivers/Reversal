## Evidence and scope

The pinned PE32 executable is SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. `0062c680` is a virtual address; its 1,909-byte body is at file offset `0x22c680` and has SHA-256 `10271964e0119f7a886c34ba8741174957ec555c822f8affa7f56acb3dab2fe6`. The `checkpoint-23` read-only export and exact-old preflight are pinned by `scripts/extract_status_refresh_24.py`. The extractor matches all 562 original Capstone instructions to the native export, including addresses, mnemonics, normalized operands and explicit memory widths. Its complete local CFG reaches all 562 starts and contains 69 branches, 27 direct calls, 11 direct nonframe writes and one `RET 4` at `0062cdf2`. All branch edges, direct call sites, memory access widths, and return sites are in `evidence/status-refresh-24-sites.json`. There are no unresolved indirect calls within this body.

This function already has the checkpoint-10 name `cm0102_refresh_player_status_row_candidate`, its R10-A comment, and a `boundary-mapped` semantic row. The name and comment remain unchanged. This report supports upgrading that **existing** row to a complete local static contract after independent review, without increasing the distinct semantic count. The numerical update and transitive effects remain unvalidated.

## Entry, initialization, and early exits

The local ABI is ECX receiver/object, one stack player pointer, `RET 4`, with an SEH frame using `FS:[0]` (`0062c680..0062c695`, `0062cde1..0062cdf2`). No meaningful return value is established. Before testing the player pointer, the body tests bits 1, 2 and 4 of byte `00b63d10`. For each absent bit it sets that bit, calls `0054a110` on `00b63d08`, `00b63d18` or `00b63d20`, and calls `0094627a` with a distinct cleanup callback (`0062c698..0062c732`). The initializer and registration effects are callee boundaries. The bit writes precede the pointer guards.

The local exits are: null player pointer (`0062c732..0062c738`); signed32 `*player >= *(int32*)00ae2364` (`0062c73e..0062c748`); null DWORD `player+61h` (`0062c74e..0062c757`); or matching two 16-bit components of the first row DWORD with `00ae2c90/+2` (`0062c77c..0062c790`). There is **no negative index guard**. Passing input requires caller-provided storage for `31 * *player` bytes after `*(DWORD*)receiver`; the 31-byte row base is formed at `0062c760..0062c76a` with 32-bit arithmetic. The cached-stamp exit occurs before date conversion, both direct RNG call sites and row writes. It also bypasses normalization of row `+e`, so callers cannot infer a valid record index merely from this function's return.

## Bounded original-entry reconstruction

`scripts/emulate_status_refresh_24.py` executes the original PE instructions from entry to `RET 4` on 13 synthetic, disjoint mapped-memory cases. The old `FS:[0]` head is zero and bits 1/2/4 are already set, so no initializer calls occur. The cases cover null player, signed count rejection, null player `+61h`, and a matching cached stamp. They execute 568 steps at 58 distinct starts. `reconstruction/status-refresh-guard.ts` implements precisely those call-free exits; `reconstruction/check-status-refresh-guard.ts` verifies path, EAX/ECX/EDX, external read order, no external data writes, ordered `FS:[0]` SEH link/unlink, preserved registers, and stack cleanup against the retained oracle. The oracle SHA-256 is `1d36facfaa5e945e4b5c66669f76bcd9ad3d793f3e8a0333728169ce8ef99cfe`.

The oracle does **not** execute any update path, initializer or callee. Normal and `python -O` extraction and emulation are byte-identical. The negative check rejects a changed specimen, changed native operand, resealed changed operand and explicit width, altered TypeScript result and tampered oracle, recording results in `evidence/status-refresh-24-negative.json`. These cases establish only the stated call-free exits; they do not validate full status refresh, calendar arithmetic, lifecycle effects or connected match outcomes.
