# R34-B: contract lookup and receiver setup frontiers

The R33-B placement checkpoint now executes its real `006eafa0 -> 004cf5f0` call on the original-produced synthetic staff and home-club pointers. It stops **before `004cf62b`**: the lookup has read source ID and count, calculated `ID*0x4f`, and loaded auxiliary-table base `DWORD[00ae2d0c] = 0` from the still-uninitialized synthetic process state. It has not read an auxiliary record, dereferenced ECX, returned a row, or resumed placement. A separate original constructor entry `004c7040` stops **before its first indirect OS call `004c7073`**, `GetLogicalDriveStringsA`. Neither bounded execution supplies the missing manager.

The specimen is the 7,192,576-byte PE32 x86 image SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`. Addresses are virtual, offsets are byte offsets, and names remain research labels. Baseline is merged main `4ee3cd0304ac34d2ed0ac09b5f97c06afc67e7f6`. The prior [R33-B evidence](action33-owner-33.md) establishes the fixture, staff, club and placement arguments through separate original producer windows and original function entries; it does not establish an enclosing live caller.

## Actual receiver provenance and lifetime

Two setup bodies write the four-byte global `00ae1050` from EAX. The selected original instructions in `00828110` allocate `0x3c` bytes at `008297ca..008297d1`, call `004c7040` only when the allocation is nonzero at `008297e7..008297ea`, and store its EAX at `008297fc`. A zero result branches away at `00829801`; a nonzero result becomes ECX for `004c7560` at `00829807..00829809`. Thus the manager seen at the placement lookup requires a successful allocator, constructor and subsequent setup path. Earlier static R12 analysis covers the initializer's row allocation and source scan, not a validated runtime completion.

The alternate body `0082a9c0` has the analogous `0x3c` allocation at `0082c7ba..0082c7c1`, calls `004c7040` at `0082c7d7`, and stores EAX to `00ae1050` at `0082c7ea`. The selected prefix stops before its subsequent setup; it does not show a call to `004c7560`. Whether this path restores rows from a save, uses a different initializer, or reaches a match is open. These are **static selected caller instructions**, not executed setup paths.

The `0082ff40` teardown reads the global at `0083036c`, conditionally calls `004c74f0` and the runtime free call, then writes EBX to `00ae1050` at `00830386`. The wider routine's prior EBX zeroing is statically evident in its export. A stored pointer is therefore bounded by setup and teardown; no persistent or cross-save ownership is inferred. The auxiliary base `00ae2d0c` has separate setup and teardown writers (`008284b7` and `008303be` in the supplied state exports). Its initialization and populated `0x4f` records are another dependency, independent of the manager pointer.

The constructor `004c7040` saves its incoming ECX in ESI at `004c7065`, installs an SEH frame, loads the `GetDriveTypeA` IAT entry to EBP, and prepares a `0xc8`-byte output buffer. Eight synthetic original-entry cases execute 16 instructions each to pre-`004c7073`, the `GetLogicalDriveStringsA` IAT call. The outgoing stack words are `(0xc8, stack_buffer)`. No manager member is written in this prefix, the global stays loader-zero, and no constructor return is inferred. The selected constructor prefix is decoded from the pinned PE; no native listing of `004c7040` was available in the pinned exports.

## Placement call ABI and precise data boundary

R33-B's original placement stops with ECX loaded from `00ae1050` (zero here), and two outgoing stack arguments `(actual_returned_staff, original_calculated_home_club)`. For each of its 80 synthetic cases, R34-B clones the **same stopped machine state**, retaining all mapped data regions, integer registers and flags, then executes the original CALL at `006eafa0` and the `004cf5f0` prefix to pre-`004cf62b`. The clone leaves the predecessor's verification state untouched; no pointer field or manager is injected into it.

The real call pushes return address `006eafa5` and presents the callee with ECX=0, `[entry ESP+4] = staff` and `[entry ESP+8] = home club`. The prefix checks both arguments nonnull, reads DWORD source ID at `004cf60c`, reads global count `00ae2364` at `004cf60e` (64 in the admitted synthetic roster), performs the signed upper-bound check, calculates `ID*0x4f`, and reads `00ae2d0c` at `004cf624`. Its next instruction, `004cf62b`, would read DWORD `[base + ID*0x4f]`; `base=0` in these cases. The selected IDs are 0–31, so this yields low addresses `0..2449`, not an original allocated auxiliary array. The harness deliberately does not execute that read, map a fabricated table, or report a lookup result. It also does not infer that ECX=0 is safe: the later `004cf635` dereferences ECX after an auxiliary index is found. If real setup succeeds, both global pointers can differ from this synthetic state.

The full static `004cf5f0` contract was mapped in [R13](contract-dependencies-13.md): ECX manager, two four-byte stack arguments, EAX row-or-zero result on normal return, callee cleanup `RET 8`, with EBX/EBP/ESI/EDI preserved. Its possible helper call and row comparisons are **not** executed here. The selected prefix has no direct RNG call and no nonstack write; that does not establish absence of later or transitive effects.

The 80 call prefixes take 20 original instructions each; eight constructor frontiers take 16 each: **1,728 original instruction steps**. Capstone 5.0.7 compares 61 selected setup/teardown/lookup instructions against pinned native operands. The constructor's 16 instructions are independently decoded from the specimen and its IAT target is checked against the PE import directory. Neither number counts R33-B's prior 25,520 steps. Full setup, OS return, row allocation/population, contract-row selection, placement after return, and live lifecycle remain unresolved.

It additionally pins SHA-256 `72a20b7d73d5212bec8fe024efff7292fcf30833220739151f0db2de33c14476` for the read-only `exports-13/004cf5f0.asm`, compares selected native operands, and records original PE ranges by virtual address, file offset and digest.
