# R37-C: bounded elevated reference capture broker

The installed version 3.9.68 game runs at administrator integrity on this host. The Codex shell has a medium-integrity token, so the reviewed [capture helper](../scripts/reference_capture_37.py) cannot open the game for memory reads from that shell. The user manually ran an administrator PowerShell inventory and an idle context snapshot. R37-C lets the coordinator issue later bounded reads without asking the user to type each command.

The [broker](../scripts/reference_capture_broker_37.py) must itself be launched through Windows `RunAs`. Windows still requires the user to approve that **one** elevation prompt; the coordinator must not act on the security dialog. After approval, the broker accepts new requests only on `127.0.0.1` for at most two hours or 120 capture requests; an active bounded capture may finish after that deadline. A 256-bit random token in an ignored local session file authenticates requests. The broker removes inherited access from that file and grants access only to the current user, Administrators and SYSTEM before writing the token. The protocol accepts `ping`, `inventory`, `snapshot`, `watch` and `stop`, with a numeric PID and (for sampled modes) one numeric thread ID. It rejects other fields, arbitrary paths and commands. A total framing deadline is capped by the broker lifetime. No raw register or memory bytes are returned over the socket.

The elevated broker loads the exact SHA-256-pinned R37-A source bytes once, and checks the on-disk source hash again before each use. R37-A still verifies the installed executable hash, target image path, live PE identity, thread ownership, bounded read sizes and output location. The broker supplies no arbitrary read regions, alternate executable, synthetic profile or alternate boundary. Each capture writes a new private JSON beneath ignored `results/`; errors are labelled and do not replace an earlier file. A source change stops new captures. The broker does not patch, inject into or debug the game; `snapshot` and `watch` briefly suspend and resume the selected thread as documented in R37-A.

The [broker checker](../scripts/check_reference_capture_broker_37.py) starts a **non-elevated test-only** broker. It verifies framing and total deadline, bad-token and bad-mode rejection, non-ASCII token rejection without server exit, rejection of extra fields, restricted session-file ACL, refusal of capture in test mode, authenticated ping, clean stop and removal of the session file. The production broker was then launched through Windows elevation and answered an authenticated ping. A coordinator-issued inventory wrote a private 8,977-byte result, SHA-256 `95a07364e5213e7a90921fc202c1650f9c2de5f2791147ae003028c02539eec1`, with zero probes and corrected no-suspension metadata. A coordinator-issued snapshot of thread 28368 wrote a private 11,326-byte result, SHA-256 `d5cab39fe2446325d21ee3c5a48673fccbf96396c779a1a29accc887e6a8ac0c`, with one complete 128-byte stack read and EIP inside `cm0102.exe` at `0x00560666`, away from `0x007023e3`. Both results remain ignored and local. This verifies autonomous elevated access to the running game, but no action-0x33 boundary or match-time RNG state.

This removes repeated PowerShell typing for capture commands. The game's elevated window has not accepted automated clicks from the approved computer-use bridge, so navigation to a relevant match still needs a separate supported input route or user gameplay. A short sampled watch can miss the brief `007023e3` boundary; a miss cannot prove the path was not executed. The local session token and private captures must remain outside Git, and the broker should be stopped when observation ends.
