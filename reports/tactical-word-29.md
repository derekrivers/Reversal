# Investigation 29-B: tactical word lookup

This unit maps virtual address `006c38f0`, a 42-byte call-free body in the pinned CM01/02 3.9.68 PE32 (SHA-256 `0c78e7da6d0bcb4603fa179449bbe6d1b6b5e1c627a22c445d14d489bd9bff86`). Its PE file offset is `0x2c38f0`. The adjacent existing helper `006c38c0` is comparison context at PE offset `0x2c38c0`, not a new semantic entry. The [site evidence](../evidence/tactical-word-29-sites.json) pins the private checkpoint-28 archive, read-only native export manifest and exact-old preflight. No executable or bulk native export is tracked.

Capstone 5.0.7 matches every original PE instruction start, mnemonic and operand against both native assembly exports: 13 instructions and 42 bytes per body. All 13 starts in each body are reachable, and each local branch/fallthrough edge stays inside its body. The sole lookup difference is the receiver's DWORD table-pointer offset: `+0x8ebc` for the existing `006c38c0` and `+0x8ec4` for `006c38f0`. The [extractor](../scripts/extract_tactical_word_29.py) checks PE32 mapping, body bytes, exact-old native identity, export hashes, complete decode and local CFG. Ghidra pseudocode for `006c38f0` suggests a 32-bit return; the assembly supports a 16-bit semantic return in AX. The existing helper's native name, comment and 2-byte return annotation are preserved.

## Local contract

ECX is the receiver pointer and entry `[ESP+4]` is a DWORD slot pointer. The helper first reads signed byte `slot+0x19` as an index. Values outside **0..10** return `AX=0`, without reading the side or table. The valid path reads signed byte `slot+0x27`, then loads a DWORD table pointer from `receiver+0x8ec4+4*signed_side` and a WORD from `table+2*index`. That WORD is AX. There is no local clamp of the side to 0/1, null check or write. An ordinary return uses `RET 4`, popping the return address and stack argument. EBX, ESI, EDI and EBP are preserved. EDX ends as the slot pointer on the invalid path and sign-extended side on the valid path; ECX changes to the table pointer only on the valid path.

The valid path's `MOVSX EAX,AL` zeroes EAX's upper half because the guarded index is 0..10. On the invalid path, `XOR AX,AX` leaves incoming EAX bits 16..31 intact. Only AX is a meaningful return. Flags are modified by the branch tests and XOR but are outside the TypeScript comparison. Prior R16 evidence lists three direct calls at `00712464`, `00712ad8` and `0071319a` with AX consumed as a tactical word or mask. The R17 dispatch mapping retains repeated lookup values as potentially distinct. This unit does not execute those connected callers or establish live match-state validity.

## Original-entry comparison

The [original-instruction oracle](../evidence/tactical-word-29-oracle.json.gz) executes both bodies from entry through `RET 4` using disjoint synthetic match, slot, table and stack memory. Per body it covers every possible index byte (256 cases) plus 49 targeted index/side combinations. The side samples include signed `-128`, `-2`, `-1`, `0`, `1`, `2` and `127`, demonstrating signed pointer indexing where mapped. Across 610 cases, all 26 instruction starts and 26 local CFG edges execute in 4,504 x86 steps.

The [TypeScript reconstruction](../reconstruction/tactical-word-29.ts) and [checker](../reconstruction/check-tactical-word-29.ts) compare all nine recorded registers including EIP/ESP, every ordered data and stack read, no writes, complete post-state SHA-256 of all four admitted memory regions, the deterministic input schedule and the observed CFG edges. The candidate new body contributes 305 of the 610 cases; the other 305 guard the existing context. The [negative receipt](../evidence/tactical-word-29-negative.json) covers normal and optimized Python regeneration, altered PE/native/manifest/preflight rejection, a resealed wrong native operand, and oracle/result/effect mutations. Node 24 and the repository check pass separately. The [exact-old proposal](../evidence/tactical-word-29-annotations-proposal.json) changes only `006c38f0` and records its 2-byte return width.

This validation is for stable, mapped synthetic memory with ordinary returns. It does not test invalid pointer faults, concurrent mutation, EFLAGS, a connected match path or tactical-plan meaning. The function label describes the observed offset and word lookup rather than a claim about game design.
